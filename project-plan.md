# 🎯 ИИ-ассистент для цифрового кампуса — План разработки

## Контекст проекта

**Задача из распоряжения:** создать концепт ИИ-ассистента для первокурсника Московского Политеха, который решает реальные проблемы: поиск информации, дедлайны, навигация, обращения.

**Что нужно сдать (Definition of Done):**
1. Таблица JTBD и карта болей
2. Анализ ТРИЗ
3. **Интерактивный прототип/MVP** — ключевой сценарий с интерфейсом, источниками данных, обработкой ошибок
4. **Архитектура и спецификация** — компоненты, RAG-контур, API, безопасность
5. Отчёт об использовании ИИ-агентов
6. Презентация (5–7 мин)

> [!IMPORTANT]
> Пункты 1, 2, 5, 6 — это работа для «исследователей» и «аналитиков» из ваших 40 человек. **Ваша команда из 8 разработчиков отвечает за пункты 3 и 4** — собственно рабочий прототип.

## Рекомендуемый стек

Ваш документ «Обоснование технологий» уже очень грамотный. Я его поддерживаю и конкретизирую:

| Слой | Технология | Почему именно это |
|---|---|---|
| **Язык** | Python 3.12+ | Все знают, весь ИИ-тулинг на нём |
| **Веб-интерфейс** | **Streamlit** | Чат делается за 30 строк кода, не нужен фронтенд. Идеально для MVP |
| **Поиск по документам** | **rank_bm25** (BM25) → опционально **ChromaDB** (векторный) | BM25 работает сразу, без GPU, без внешних сервисов. Chroma — если захотите сравнить |
| **LLM API** | **GigaChat API** или **YandexGPT** (российские, бесплатные тарифы для студентов) / fallback: OpenAI-совместимый API | Telegram запрещён — значит, наверняка хотят «импортонезависимость». GigaChat даёт бесплатные токены |
| **Парсинг документов** | **PyMuPDF** (PDF) + встроенный Python (txt, md) | Уже установлен, работает |
| **Хранение знаний** | Папка `data/` с txt/md/pdf + JSON-индекс | Просто, понятно, любой может добавить файл |
| **Конфиг и секреты** | **python-dotenv** + `.env` файл | Ключи не попадают в Git |
| **Командная работа** | **GitHub** + ветки + PR | Стандарт |

> [!TIP]
> **Не усложняйте.** Для 30–50 документов кампуса BM25 работает отлично. Векторный поиск — это бонус, а не обязательность. FastAPI + React — это «взрослая» архитектура, но вам нужен **работающий MVP**, а не красивый фронтенд.

## 👥 Распределение на 8 человек

> [!NOTE]
> Все будут вайбкодить — это ок. Главное — чёткие границы модулей, чтобы не мешать друг другу. Каждый работает **в своей папке / файле**, мёржит через PR.

### Пары и задачи

| # | Роль | Кто | Что делает | Файлы |
|---|------|-----|------------|-------|
| **1** | **Ты (тимлид)** | 1 человек | Архитектура, код-ревью, интеграция, `.env`, `rag_chain.py`, финальная сборка | `core/rag_chain.py`, `app.py`, общая координация |
| **2** | **Загрузчик документов** | 1 человек | Парсинг PDF/TXT/MD → разбивка на чанки с метаданными (источник, дата) | `core/document_loader.py` |
| **3** | **Индексатор + Поиск** | 2 человека (пара) | BM25-индекс, опционально Chroma. Функция `search(query) → list[Chunk]` | `core/indexer.py`, `core/retriever.py` |
| **4** | **LLM-клиент** | 1 человек | Обёртка API (GigaChat/YandexGPT), промпт-инжиниринг, обработка ошибок | `core/llm_client.py` |
| **5** | **Streamlit UI** | 2 человека (пара) | Чат-интерфейс, страница админа, кнопка «Не помогло», отображение источников | `app.py`, `pages/admin.py` |
| **6** | **Тестировщик + Данные** | 1 человек | Набор 30–50 тестовых вопросов, скрипт метрик, `contacts.json`, подготовка документов | `tests/`, `config/`, `data/` |

### Почему именно так

- **Пары на сложных частях** (поиск и UI) — два человека быстрее разберутся и подстрахуют друг друга
- **Модули независимы** — загрузчик не зависит от LLM-клиента, UI не зависит от индексатора
- **Каждый может работать параллельно** — достаточно договориться об интерфейсах функций

## Интерфейсы между модулями (контракты)

Чтобы 8 человек работали параллельно, нужно заранее договориться о формате данных:

```python
# === Общие типы (core/__init__.py) ===

from dataclasses import dataclass

@dataclass
class Chunk:
    """Один фрагмент документа."""
    text: str           # Текст фрагмента (300–500 слов)
    source: str         # Название файла-источника
    page: int | None    # Номер страницы (для PDF)
    date: str | None    # Дата обновления документа

@dataclass  
class SearchResult:
    """Результат поиска."""
    chunk: Chunk
    score: float        # Релевантность (больше = лучше)

# === Загрузчик (document_loader.py) ===
def load_documents(folder: str) -> list[Chunk]:
    """Читает все файлы из папки, возвращает список чанков."""
    ...

# === Индексатор (indexer.py) ===
def build_index(chunks: list[Chunk]) -> None:
    """Строит и сохраняет индекс."""
    ...

# === Поисковик (retriever.py) ===  
def search(query: str, top_k: int = 5) -> list[SearchResult]:
    """Ищет top_k самых релевантных чанков."""
    ...

# === LLM-клиент (llm_client.py) ===
def generate_answer(query: str, context: list[Chunk]) -> str:
    """Генерирует ответ по контексту. Возвращает текст с источниками."""
    ...
```

> [!IMPORTANT]
> Эти интерфейсы — ваш «договор». Пока все возвращают правильные типы данных, модули работают вместе. Каждый может внутри своего модуля делать что угодно.

## Что по LLM провайдеру?

| Провайдер | Плюсы | Минусы |
|-----------|-------|--------|
| **GigaChat (Сбер)** | Бесплатный тариф для физлиц, российский, хорошо знает русский | Регистрация через Сбер ID |
| **YandexGPT** | Бесплатный грант для студентов, российский | Нужен аккаунт Яндекс.Облака |
| **OpenAI API** | Лучшее качество, простой API | Платный, зарубежный, может быть проблема с оплатой |
| **Ollama (локально)** | Бесплатно, без интернета | Нужна мощная машина (8+ ГБ RAM), качество хуже |

> [!TIP]
> **Рекомендация:** начните с GigaChat — бесплатно, по-русски, API простой. Код написан так, что провайдера можно поменять за 10 минут (просто подменить `llm_client.py`).
